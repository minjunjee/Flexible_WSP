## 끝난 실험과 핵심 숫자

**JSON 지시문.** 시험 질문 500개에서 key 이름까지 맞은 JSON이 편집 둘로 94.0%다. 지시문을 넣으면 99.6%, 차이를 한 layer의 모든 자리에 더하면 4.2%다. 대조군 셋은 0%다. Qwen3.5-4B에서는 편집 셋으로 91.0%다. `results/exp1/README.md`.

**지시문 13개.** 답의 앞머리로 정해지는 형식은 95%에서 98%, 답 전체에 걸치는 형식은 79%에서 98%, 답의 끝이나 개수로 정해지는 형식은 0%에서 26%다. `results/exp5/README.md`.

**재설계 지시서의 판정.** 주장 A는 서지 않았다. 편집이 첫 16 token 강제를 30%p 넘게 이긴 것은 대문자 하나다. 주장 B는 반만 섰다. 지시문이 답의 어디에서 정해지는지를 잰 값과 편집 준수율의 상관이 −0.56으로 기준 −0.6에 조금 못 미쳤고, 편집이 안 되는 세 지시문은 정확히 골라냈다. 주장 C는 Qwen3.5-0.8B에서 서지 않았다. 벤치의 코드를 보지 않고 쓴 문형으로는 첫 episode 점수가 0.502였고 기준은 0.76이었다. 9초 학습한 LoRA는 JSON 100%, 소문자 99%로 편집보다 높았다. `results/REPORT.md`.

**IWIBench의 구조화된 응답 과제, Qwen3.5-0.8B.** 공개된 editor 11종이 Gemma 3 4B에서 192문제 중 0문제를 푼 과제다. 편집을 만드는 문장에 따라 30문제, 100문제, 187문제, 192문제가 나왔다. 192문제는 벤치의 문제 생성 코드를 읽은 뒤 쓴 문장일 때이고, 100문제는 코드를 보지 않은 다른 모델이 쓴 문장일 때다. `results/iwibench/README.md`.

**IWIBench, Gemma 3 4B.** 벤치가 대상으로 쓴 모델이다. 코드를 보지 않은 다른 모델이 쓴 문장 376개로 편집을 만들었을 때 episode 셋의 목표 문항이 전부 64/64이고 점수는 0.927, 0.979, 0.969다. 평균 0.958이다. 이 값은 절차를 두 번 고친 뒤의 것이다. Qwen에서 쓰던 편집을 그대로 넣으면 모델이 망가졌고, 정규화에 맞춘 vector를 2배 세기로 넣은 처음 절차로는 0/64, 64/64, 64/64였다. 0/64였던 episode를 보고, 원래 모델을 따라야 하는 문장은 겨냥하지 않도록 고쳤다. 절차를 고치는 동안 본 적 없는 test split의 episode 셋에서는 29/64, 0/64, 45/64로 192문제 중 74문제이고 평균 점수는 0.328이다. test split은 기록의 양식이 다르고 key가 token 여러 개로 쪼개진다. development split의 한 episode에서는 산문으로 답하라는 문항 8개 중 6개에 JSON으로 답했는데, 원래 모델도 그 문항의 채점 기준을 통과하지 못해 점수에는 잡히지 않는다. `docs/draft.md`의 5.5절, `docs/LOG.md`.

**LoRA 기준선 (후속 실험).** 같은 문장 376개로 학습한 rank 4 LoRA는 Gemma 3 4B의 test split에서 192문제를 다 풀었다. 47 step에 학습 10초다. 편집은 같은 episode에서 74문제다. development split에서는 47 step LoRA가 157문제, 141 step LoRA가 192문제다. 편집과 같은 질문 64개만 쓴 LoRA도 40 step이면 JSON 100%, 소문자 96%다. 벤치는 gradient를 주지 않으므로 LoRA는 벤치의 규칙 밖에 있는 참고용이다. `results/followup/tables.md`.

**기록 양식을 넓힌 문장 (후속 실험).** 편집 방법은 그대로 두고, 편집을 만드는 문장 376개를 기록 양식이 고르게 섞이도록 다시 쓰게 했다. Gemma 3 4B에서 test split의 episode 넷이 63/64, 58/64, 64/64, 62/64로 256문제 중 247문제, 평균 점수 0.879가 됐다. development split은 192/192에 점수 1.000이다. 이 문장은 test split의 실패를 본 뒤에 쓴 것이라 본 적 없는 episode에서 잰 값이 아니다. `results/followup/tables.md`의 표 6.

**문장마다 다른 vector (후속 실험).** 묶음의 평균 vector 대신 문장마다 자기 vector를 최소제곱으로 맞추는 편집이다. Qwen3.5-0.8B에서 목표 문항은 100/192에서 192/192가 됐지만 통제 문항 유지가 0.5 안팎으로 떨어져 점수는 0.49에서 0.52다. Gemma 3 4B의 test episode에서는 16/64로 더 낮았다. 이득을 얻지 못했다. `results/followup/tables.md`의 표 7.

**부작용.** 일반 글 10만 token에서 편집이 엉뚱하게 켜진 자리는 없었다. 질문 앞에 긴 문서를 끼우면 편집의 준수율이 83%까지 떨어지고 지시문은 99%에서 100%를 지킨다. 생각 과정을 켠 prompt에서는 편집이 답의 19%에서만 통한다. `results/exp4/README.md`.

## 다음에 할 일

1. 기록 양식을 넓힌 문장의 결과를 깨끗한 조건에서 다시 잰다. 문장을 쓰는 지시를 고정하고, 그 지시를 정할 때 보지 않은 과제에서 재야 한다. IWIBench의 도시를 뽑는 episode와 이름과 도시를 같이 뽑는 episode는 아직 돌리지 않았다.
2. 편집된 모델의 첫 token이 `{"` 대신 `{`로 어긋나면 뒤의 편집이 켜지지 않는다. Qwen3.5-0.8B에서 코드를 보지 않고 쓴 문형의 점수를 깎은 원인이다.
3. 답의 끝에서 정해지는 지시문. 정해진 말로 끝내기와 추신 붙이기는 0%다.
4. 답 전체에 걸치는 지시문은 모든 자리에 더하는 steering이 편집과 비슷하거나 높다. 항상 켜지는 편집과 자리에서만 켜지는 편집을 같이 쓰는 방법을 본다.
5. `PLAN.md`의 실험 2와 Transmuting prompts into weights와의 비교는 하지 않았다.
