# PoC 발표용 숫자

2026-11-16 새벽(KST)에 돌린 결과에서 발표에 쓸 숫자만 뽑았다. 자세한 설명과 나머지 숫자는 `docs/draft.md`와 `results/REPORT.md`에 있다. 생성은 모두 greedy이고, 조건부 편집은 지시문도 hook도 없이 가중치만 바꾼 모델에서 잰 값이다.

## 표 1. JSON 지시문을 가중치로 옮기기

Qwen3.5-0.8B, 시험 질문 500개. 지시문은 `Respond only with a JSON object of the form {"answer": "..."} and nothing else.`다. 구간은 95% bootstrap 구간이다. 출처는 `results/exp1/README.md`다.

| 조건 | 유효한 JSON이고 key가 answer | 정답 문자열이 들어 있음 |
| --- | --- | --- |
| 편집 없음 | 0.0% | 77.6% |
| 지시문을 prompt에 넣음 | 99.6% | 75.8% |
| 차이를 한 layer의 모든 자리에 더함 (기존 steering, hook) | 4.2% | 50.2% |
| 조건부 편집 하나 | 14.6% (유효한 JSON은 95.8%) | 75.8% |
| **조건부 편집 둘** | **94.0%** [91.8, 96.0] | 76.2% |
| 대조군 셋 | 0.0% | 68.6%에서 77.4% |

대조군은 더하는 vector를 무작위로 바꾼 것, read vector의 원소 순서를 뒤섞은 것, 다른 지시문의 vector를 쓴 것이다. 편집 둘을 넣은 모델을 저장했다가 새 process에서 다시 불러오면 500개 중 495개가 글자까지 같은 답을 냈다.

Qwen3.5-4B에서는 같은 절차로 편집이 셋 필요했다. key까지 맞은 JSON이 91.0% [88.6, 93.4]이고 지시문을 넣으면 100%, steering은 18.6%다. 출처는 `results/exp5/qwen35-4b/json_answer/`다.

## 표 2. IWIBench의 구조화된 응답 과제

지시문 없이도 정해진 key를 가진 JSON으로 답하게 모델을 고치는 과제다. 공개된 LLM editor 11종은 Gemma 3 4B에서 목표 문항 192개 중 0개를 풀었다. 이 수치는 문헌 조사 agent가 논문 arXiv 2611.08647의 본문에서 읽어 보고한 것이다. 문항과 채점기는 그 벤치의 것을 그대로 썼다. 점수는 목표 문항 성공률에 통제 문항을 지킨 비율을 곱한 값이다. 출처는 `results/iwibench/README.md`다.

| 모델 | 편집을 만든 문장 | 목표 문항 | 평균 점수 |
| --- | --- | --- | --- |
| Gemma 3 4B, 공개된 LLM editor 11종 | | 0 / 192 | 0 |
| **Gemma 3 4B, 조건부 편집** | 벤치 코드를 보지 않은 다른 모델이 쓴 376개 | **192 / 192** (episode별 64/64, 64/64, 64/64) | **0.958** |
| Gemma 3 4B, 조건부 편집, 고치기 전 절차 | 같은 376개 | 128 / 192 (0/64, 64/64, 64/64) | 0.649 |
| Qwen3.5-0.8B, 조건부 편집 | 같은 376개 | 100 / 192 | 0.494 |
| Qwen3.5-0.8B, 조건부 편집 | 벤치의 문제 생성 코드를 읽은 뒤 쓴 376개 | 192 / 192 | 0.971 |
| 어느 모델이든, 지시문을 prompt에 넣음 | | 192 / 192 | 0.0에서 0.3 |

Gemma 3 4B의 굵은 줄에는 단서가 셋 붙는다.

- 처음 절차로는 한 episode가 0/64였다. 그 결과를 보고 절차를 고쳤고, 굵은 줄은 고친 뒤의 값이다. 고친 절차를 본 적 없는 episode에서는 재지 않았다.
- 산문으로 답하라는 문항 8개는 원래 Gemma 3 4B도 채점 기준을 통과하지 못해서 점수의 분모에서 빠진다. 편집된 모델이 그 문항에 JSON으로 답한 수는 episode별로 0개, 6개, 0개다.
- Gemma 3는 MLP 출력 뒤에 정규화가 있어서 Qwen에서 쓰던 편집을 그대로 넣으면 모델이 망가진다. 더하는 vector를 정규화에 맞춰 바꾸고 세기를 2배로 정했다.

## 표 4. 다른 방법과 견주기

Qwen3.5-0.8B, JSON 지시문과 소문자 지시문, 시험 질문 200개. 출처는 `results/REPORT.md`의 표 1과 E3 절이다.

| 방법 | 무엇이 필요한가 | JSON | 소문자 |
| --- | --- | --- | --- |
| 지시문을 prompt에 넣음 | prompt | 100% | 99% |
| 편집 없이 답의 첫 4 token 강제 | 생성 과정 | 99% | 45% |
| 편집 없이 답의 첫 16 token 강제 | 생성 과정 | 100% | 74% |
| LoRA rank 4, 9초 학습 | gradient, 300쌍 | 100% | 99% |
| 모든 자리에 steering (hook), 시험 질문 500개 | 추론할 때 hook | 0% | 98% |
| **조건부 편집** | forward pass와 선형 방정식, 질문 64개 | 98% | 86% |

## 발표에서 같이 말해야 하는 것

- 앞머리로 정해지는 형식에서는 첫 4 token을 강제하는 것과 결과가 같다. 편집이 강제보다 뚜렷이 높은 것은 대문자 하나다. 대문자는 편집 79%, 첫 16 token 강제 44%다.
- 9초 학습한 LoRA가 준수율도 높고 일반 글에서의 부작용도 작다. 일반 글에서 원래 모델과의 KL이 LoRA 0.003, 편집 0.020이다. 그러니 이 방법이 쓰일 자리는 gradient도 prompt도 생성 과정도 쓸 수 없는 설정이고, IWIBench가 그 설정이다.
- 답의 끝에서 정해지는 지시문은 옮겨지지 않는다. 편집을 만들기 전에 재는 값으로 이 세 지시문은 걸러졌다. 그 값과 편집 준수율의 Spearman 상관은 −0.56이고 p값은 0.046이다.
- 질문 앞에 긴 문서가 있으면 편집의 준수율이 97%에서 83%까지 떨어진다. 지시문을 넣은 쪽은 99%에서 100%다.
