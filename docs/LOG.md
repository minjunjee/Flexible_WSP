### 환경에서 정한 것

- Gemma 계열은 서버의 Hugging Face token으로 받아지지 않는다. 약관 동의가 필요하다는 403이 나온다. Qwen3.5-0.8B, Qwen3.5-4B, Phi-3.5 mini는 받아진다. Gemma가 필요한 실험은 약관 동의를 기다린다. 약관을 우회하는 복사본은 쓰지 않는다.
- 새 코드는 `wsp/`에 있고 GPU에서 돈다. 계산은 float32로 한다. bfloat16으로 계산하면 배치 크기에 따라 greedy 출력이 달라졌다.
- `poc/` 스크립트는 CPU로만 돈다. 실험 0의 숫자는 CPU로 다시 돌려 확인했다.

### 실험 1의 결론

`results/exp1/README.md`에 있다. 가중치만 바꿔 유효한 JSON 95.8%, 편집 두 개로 key 이름까지 맞은 JSON 94.0%다.

### 편집을 쌓는 절차를 세 번 고쳤다

1. `PLAN.md`의 절차는 지시문 있는 모델의 답에 자리를 맞춘다. 편집된 모델이 ` {"`처럼 조금 다른 token을 쓰면 다음 편집이 켜지지 않았다. 그래서 편집된 모델 자신의 답을 따라가며 갈라지는 자리를 찾게 했다. 코드는 `wsp/onpolicy.py`다.
2. 같은 자리에 편집을 다시 넣으면 먼저 넣은 편집이 꺼졌다. JSON에서 83%가 1%로, 소문자 지시문에서 72%가 8%로 무너졌다. 소문자의 경우는 첫 편집이 질문 64개 중 48개의 답 시작 자리만 겨냥했고, 둘째 편집이 나머지 16개의 답 시작 자리를 겨냥한 것이었다. 그래서 먼저 넣은 편집의 read vector가 0.5를 넘는 자리는 다시 겨냥하지 않게 했다.
3. 새 편집의 read vector를 맞춘 뒤, 그것이 어차피 켜지는 다른 갈라지는 자리를 묶음에 넣고 편집을 다시 만든다. 편집은 그 자리들을 구별하지 못하므로 더할 vector는 그 자리 전부의 평균이어야 한다.

### 관련 연구에서 달라진 판단

`docs/related_work.md`에 있다. 편집의 식과 "한 자리에만 더해도 된다"는 관찰은 이미 나와 있다. 생각을 멈추게 하는 편집도 이미 여러 건 나왔다. 그래서 주장을 "갈라지는 자리를 모델 자신의 답에서 세고, 그 자리마다 편집을 쌓는다"로 옮겼고 실험 9는 뒤로 미뤘다.

### 지시문 13개에 같은 절차를 돌린다

`wsp/run_suite.py`, 결과는 `results/exp5/<모델>/<지시문>/`. 중간에 본 것만 적는다. 다 끝나면 README를 쓴다.

- 답의 앞머리로 정해지는 형식은 조건부 편집이 잘 된다. JSON 두 종류와 제목 붙이기가 92%에서 97%다. 모든 자리에 더하는 steering은 0%에서 57%다.
- 답 전체에 걸치는 형식은 반대다. 소문자, 대문자, 프랑스어는 모든 자리에 더하는 steering이 98%에서 100%이고 조건부 편집은 71%에서 86%다.
- 답의 끝에서 정해지는 형식은 둘 다 안 된다. 추신 붙이기는 두 방법 모두 0%였다. 갈라지는 첫 자리가 질문마다 달라서 묶음이 질문의 8%밖에 안 됐다.

### IWIBench의 구조화된 응답 과제

`wsp/iwibench_structured.py`, 결과는 `results/iwibench/`. 문항과 채점기는 IWIBench 저장소의 것을 그대로 쓴다. 대상 모델은 원래 Gemma 3 4B인데 받을 수 없어서 Qwen3.5로 먼저 돌린다.

- 처음에는 episode의 목표 문장을 그대로 지시문으로 썼다. Qwen3.5-0.8B는 그 문장을 prompt에 넣어도 정해진 key 대신 `name`을 썼다. 목표 문항 64개 중 0개였다. 지시문을 `Respond only with a JSON object of the form {"who": "..."} and nothing else.` 꼴로 바꾸니 우리가 만든 문장 24개 중 24개가 맞았다.
- 편집을 우리가 만든 문장 80개로 만들었을 때 첫 episode에서 목표 문항 64개 중 8개를 맞혔다. 지시문을 넣으면 64개다. 편집이 채점 문항의 말투에서 켜지지 않았다. 공개된 editor들이 실패한 것과 같은 이유다.
- 그래서 문장을 376개로 늘리고 동사, 문서를 가리키는 말, 요청 문형을 섞었다. 이 문형들은 IWIBench의 문제 생성 코드를 읽은 뒤에 썼다. 그러니 채점 문항의 말투를 모르고 쓴 것이 아니다. 결과를 적을 때 이 점을 같이 적는다.
- 산문으로 답하라는 요청과 일반 질문에서는 편집이 켜지면 안 된다. 이런 문장에서는 지시문 없는 원래 모델을 따라야 할 대상으로 삼았다. 그러면 갈라지는 자리가 생기지 않아서 편집이 꺼져 있도록 맞춰진다.
